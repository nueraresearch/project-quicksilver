# C0 cutover inventory (draft)

- **Status:** Draft for owner review — no cutover, migration, schema change, or provider change is authorized by this document.
- **Date:** 2026-11-17
- **Scope:** The mapping deliverable for C0 in [native CMS cutover](native-cms-cutover.md). This inventories the current Sanity content plane and records a target disposition. It does not implement the target.
- **Sources inspected:** all 36 files registered by `apps/studio/schemas/index.ts`; the 48 `apps/web/app/api/**/route.ts` files and their 51 exported operations; the Sanity stores and query modules under `apps/web/lib`; `packages/operator`; the host stores used by Genesis, Aura, shadow mode, telemetry, and departments; the Studio schema/config, scripts, and seed files; and the Context MCP wiring under `packages/agent`.
- **No production data was exported.** Counts below are schema, seed, and call-site counts, not production document counts. The C0 data inventory by tenant, draft state, references, assets, and deletions still requires a read-only export and is not claimed here.

## 1. Disposition rules

| Disposition | Meaning in this inventory |
|---|---|
| **Native** | The authoritative record moves to a Quicksilver-owned collection/repository. Native is the writer and normal read path; Sanity is not required. |
| **Derived** | The record is generated by a native operation, kernel decision, host run, or agent evaluation. It is still durable and often append-only, but it is not editorial content authored in Studio. It moves to a native derived/audit store and is retained; "derived" does not mean disposable. |
| **Optional adapter** | The path remains Sanity-specific, OIDC-specific, or otherwise provider-specific. It may support migration or an explicitly selected deployment, but it may not be required by the default build, CI, seed, or runtime. |
| **Retirement — owner approval required** | The feature is proposed for removal. It is **not approved** by this draft. The Product Owner must sign the removal and the migration note before C0 can exit. |

No schema type, route, query family, Studio action, seed, or Context MCP tool is intentionally left unclassified.

## 3. Route inventory

The repository has **48 route files and 51 exported operations**. `docs/api/openapi.json` declares the same **51 operations**, and `apps/web/lib/app-routes.test.ts` asserts that the route sources and the contract match exactly. Route dispositions below count operations: **34 native, 12 derived, 5 optional adapter, 0 retirement.**

### The "46 importable handlers" figure

The matrix's 46 is neither a second route inventory nor a count of unimportable operations. It is the P-118 count recorded at commit `3f7261c` (2026-10-09, PR #114), when the tree had **45 route files and 46 exported operations**. The operator layer in commit `c8938d6` (2026-10-13, PR #120) added exactly three route files and five operations:

| Added route file | Added operations |
|---|---|
| `apps/web/app/api/operator/calendar/route.ts` | `GET`, `POST` |
| `apps/web/app/api/operator/queue/route.ts` | `GET` |
| `apps/web/app/api/operator/reviews/route.ts` | `GET`, `POST` |

45 + 3 = 48 route files; 46 + 5 = 51 operations. No other route file or exported method differs between `3f7261c` and current HEAD. The entire delta is the operator calendar, queue, and reviews routes.

The P-118 harness in `apps/web/lib/api-response-schema.test.ts` is not a 46-route allow-list. `loadHandlers()` walks every `app/api/**/route.ts`, dynamically imports each module, enumerates every exported `GET`/`POST`/`PUT`/`PATCH`/`DELETE`, records a module as `unimportable` if its import throws, and skips it. It then validates each 2xx/3xx response body against the operation's declared OpenAPI success schema. The test asserts a floor of 35 validated responses, no 400/422 request-validation refusal, and no operation without a declared success response. It has **no 46 assertion and no assertion that `unimportable` is empty**; that count is only printed under `QS_SCHEMA_REPORT=1`. A current run at HEAD reported:

| P-118 bucket | Count |
|---|---|
| operations enumerated | 51 |
| validated against the declared schema | 37 |
| not successful (401/500/503) | 14 |
| unimportable route modules | 0 |

The exact reconciliation is therefore **46 -> 51 operations, not 46 -> 48**: five exported operations across three added route files. `app-routes.test.ts` remains the source-level 48-file / 51-operation drift guard; the response-schema harness is the invocation guard and currently reaches all 51, validating 37. The older "42 of 46" credential-baseline statement is a pre-operator snapshot, not the current invocation result; today 14 of 51 operations are not successful because they need seeded data, a model provider, or another unconfigured dependency.

## 8. Tenant-scope gaps

**Finding:** no current web query derives tenant scope from the authenticated principal. `guardWebRoute` authenticates and authorizes the caller, but its success result exposes only `principalId`; it drops the principal's `tenantId`. Sanity queries therefore either have **no tenant predicate** or use `QUICKSILVER_TENANT_ID` from process configuration. The OIDC path checks the browser session's tenant against that environment value, but the query still uses the environment value, not the principal. This is a deployment-scoped single-tenant assumption, not tenant isolation.

**Counts:** 23 of the 36 schema types have no tenant-like field; 10 have `tenantId`; 3 use `companyId`. `companyId` is a legacy name, not a proven equivalent, and must be normalized or mapped explicitly in C1.

### 8.1 Types with no tenant field (23)

### 8.4 Cross-cutting C1/C2 gate

- **C1:** every retained collection and relation gets a required tenant key, including audit and join records; `companyId` is normalized; uniqueness is tenant plus business key; existing documents receive an explicit tenant, never an implicit default.
- **C2:** `guardWebRoute` must return the authenticated principal's tenant; repository/query functions must take that tenant as a required argument; an authenticated route must not fall back to `QUICKSILVER_TENANT_ID`.
- **C2:** every list, count, aggregate, detail, mutation, audit export, queue bucket, and dashboard total includes tenant; a cross-tenant ID returns 404, not 403 and not a foreign record.
- **C2:** every write stamps the principal tenant and verifies each reference resolves in that tenant; relation writes fail closed on a cross-tenant or unresolved reference.
- **C2:** tests use two tenants and prove that calendar, queue, reviews, entities, both dashboards, decisions, inbox, plan, and memory cannot see or count the other tenant's records.
